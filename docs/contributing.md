# 프로젝트 변경 관리

변경은 작업 브랜치에서 작성하고 Pull Request를 통해 main에 반영한다.

## 작업 순서

1. 최신 main에서 작업 브랜치를 만든다.
2. 코드를 수정하고 로컬에서 검증한다.
3. 변경 내용을 커밋하고 작업 브랜치를 Push한다.
4. main을 대상으로 Pull Request를 만든다.
5. 변경 내용과 CI 결과를 확인한다.
6. 필수 검사가 통과하면 병합한다.

## 필수 CI 검사

- FastAPI tests
- Terraform checks

## main 보호 규칙

- Pull Request를 통해 변경한다.
- 필수 CI 검사가 성공해야 병합할 수 있다.
- 최신 main을 기준으로 검증한다.
- 관리자에게도 보호 규칙을 적용한다.
- 강제 Push와 브랜치 삭제를 허용하지 않는다.
